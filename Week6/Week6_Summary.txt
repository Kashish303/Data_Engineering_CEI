Step 1 – Understanding Apache Spark Architecture

The assignment started with understanding how Apache Spark works internally before writing any code.

I studied the complete architecture of Spark, including the Driver Program, Cluster Manager, Executors, Task Scheduling, Resource Allocation, and Distributed Processing.

Instead of writing only definitions, I added architecture diagrams and explained how these components communicate with each other during Spark job execution. I also connected these concepts with the Databricks environment to understand how Spark applications are executed in practice.

Step 2 – Understanding Spark Execution

Before performing DataFrame operations, I studied Spark's execution model.

I explored concepts such as Lazy Evaluation, Logical Plans, Physical Plans, DAG Generation, and the Catalyst Optimizer.

Rather than only learning the theory, I used df.explain(True) to inspect Spark's execution plan and understand how Spark optimizes transformations before execution.

Execution plan screenshots and observations were also included to strengthen the explanation.

Step 3 – Reading and Exploring the Dataset

The dataset was loaded into Databricks using PySpark.

Before applying any transformations, I validated the dataset by checking:

Columns

Sample Data

This step helped ensure that the dataset was correctly loaded and that all columns had the expected data types.

I also understood why validating data before processing is an important step in real-world ETL pipelines.

Step 4 – Understanding Storage Formats

I explored the differences between CSV and Parquet file formats.

Instead of comparing them theoretically, I studied:

Row-based storage
Columnar storage
Compression
Query Performance
Memory Utilization

I also explained why modern Data Engineering platforms prefer Parquet over CSV for analytical workloads and how it improves Spark performance.

Step 5 – Performing DataFrame Transformations

After understanding the Spark architecture and dataset, I implemented various DataFrame operations.

These included:

Filtering rows
Selecting required columns
Renaming columns
Creating new columns

Applying conditional filters

Every transformation was followed by validation to verify that the output was correct.

To improve readability, I displayed only the required columns instead of printing the complete DataFrame.

Step 6 – Understanding DataFrame Immutability

While renaming columns and changing data types, I studied Spark's DataFrame Immutability.

Instead of assuming that transformations modify the original DataFrame, I verified that every transformation creates a new DataFrame while leaving the original DataFrame unchanged.

This concept was demonstrated by comparing the schemas before and after performing transformations.

Step 7 – Understanding Spark Fault Tolerance

I explored how Spark handles failures in distributed environments.

The notebook explains:

Lineage Graph
Directed Acyclic Graph (DAG)
Partition Recovery
Worker Node Failure
Fault Tolerance

Instead of only explaining these concepts theoretically, I used diagrams to illustrate how Spark recreates only the failed partitions without restarting the complete application.
